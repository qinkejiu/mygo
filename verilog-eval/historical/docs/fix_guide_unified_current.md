## Current Goal

Undo the benchmark-interface output-binding regression first.

Do not spend time on behavioral mismatches until this systemic compile failure is fixed.

## Root Problem

The current compiler/backend no longer maps benchmark-visible expected outputs to implementation-side output bindings correctly.

Representative errors:

- `backend: build benchmark interface wrapper: no implementation binding found for expected output zero`
- `backend: build benchmark interface wrapper: no implementation binding found for expected output out`
- `backend: build benchmark interface wrapper: no implementation binding found for expected output z`

Interpretation:

- this is one dominant regression, not 146 unrelated failures
- the benchmark wrapper can still see what outputs are expected by the testbench
- but it can no longer resolve those names to implementation bindings generated by the compiler

## Likely Root Causes

1. The benchmark interface wrapper now expects benchmark-visible names, but emitted implementation outputs are no longer exposing compatible bindings.
2. Internal `out_*` globals may still exist, but the name-mapping layer between implementation outputs and benchmark wrapper outputs is broken.
3. Output binding metadata may have been removed, renamed, or filtered incorrectly during IR or backend emission.
4. The wrapper-building path may now require a binding field that is missing for most outputs.
